# v7.0 預覽：手機表格版面全面整理（作者 2026-09-20：「有些表格好像版面不美觀。全部重新檢查。」）

Fable 在 375px、摺疊全開實測全書 46 張表（`document.querySelectorAll('table')` 的順序，編號 0–45）。問題不只是「要不要左右滑」，而是三種難看：
(1) **短字被折行**：「−37%～」／「+52%」、「少 40」／「萬」、欄名「股票跌」／「40%」；
(2) **文字多的表被擠成一欄兩三個字**：第 24 節借貸四件事表一格 23 行、整張 1,853px 高；第 14 節完整計畫表 5,632px；
(3) 橫向滑動時第一欄（列名）滑走，看不出這一列是誰。

**只動排法，不改任何文字與數字**（欄名裡加 `<br>` 控制斷行可以；縮寫欄名不行）。電腦版與列印版的樣子不變：所有新規則都包在 `@media screen and (max-width:660px)`。先讀 `v7-builder-rules.md`。

## 做法一：文字多的表 → 手機上「一列一張小卡」

- HTML：在指定的 `<table>` 加 class `stack-mobile`（只加 class，不動內容）。
- JS（加在現有行內 script）：對每張 `table.stack-mobile`，把表頭各欄文字寫進同欄每個 `td` 的 `data-label`（第一欄不用）；寫完才給 table 加 `is-stacked`。CSS 只對 `table.stack-mobile.is-stacked` 生效——沒有 JS（工作表、短稿）就維持原表格。表頭有 `colspan`／多列表頭的表不適用，遇到就回報。
- CSS（≤660px）：`thead` 視覺隱藏（保留給螢幕閱讀器）；`tr` 變成一張卡（block、邊框、圓角、卡與卡之間留白）；第一格當卡片標題（粗體、底色同現有表頭）；其餘每格 `display:block`，前面用 `td::before{content:attr(data-label)}` 顯示欄名（小字、次要色、獨立一行或同行「欄名：內容」，你挑好讀的）；空格（「—」或空字串）照樣顯示。`.table-wrap` 在這種表上不需要橫向捲動。深色模式顏色同步。
- 第一欄是空表頭（左上角空白）的表：第一格本來就是列名，直接當卡片標題。
- 適用（編號＝實測順序；請用節 id＋表頭核對，不要只信編號）：
  - 5（`s4`，市場／高點到再創高／約多久／查核說明）
  - 7（`s5`，配置 × 連續 1／5／10／20 年的報酬範圍）——每種配置一張卡，四行「連續 N 年：範圍」
  - 18（`s11`，起步版這一行／在哪一節填過／完整版哪幾格）
  - 20（`s11`，完整計畫表：區／格／怎麼填／擋住哪個錯，4×25）
  - 34（`cases`，陳大哥：投資圈／股債比／防守放／跌 40／50／60%／幾年要自己補，7 欄）
  - 35（`cases`，**主線**，四位示範人物一起比）——這張的「卡」應該是**一個人一張**（欄是人、列是項目），也就是要以「欄」為單位疊；做法：JS 為這張表在手機上產生轉置後的卡片（class `stack-mobile-cols`），或在 HTML 裡另放一份只在手機顯示的轉置版——**不要複製內容進 HTML**（字數、哨兵、numbers 都會重複計算），用 JS 轉置。沒有 JS 時維持原表格＋橫向捲動。
  - 36、37（`s12`，問題／教學上的通則／去哪一節）
  - 38（`s12`，A 只用台灣券商／B 複委託／C 機器人理財…，三條路比較）——同 35，欄是「路」，以欄為單位疊（`stack-mobile-cols`）
  - 40、41、42（`costs`，項目／發生時間／檢查方式；哪一層／什麼時候發生／怎麼算／例子；發生什麼事／你的持股還在嗎／會怎樣／你要做什麼）
  - 44（`lifecycle`，借貸四件事：借法／期限多長／利率多低／要不要還本／會不會被斷頭）
- 兩欄的表（0、16、19、27、32、39…）不疊，維持表格；但若第一欄被擠到每行不到 4 個字，調欄寬比例（`col` 或第一欄 `min-width`）。

## 做法二：數字表 → 不折行、變緊湊

- 數字／短字儲存格不折行：給數字格 `white-space:nowrap`（現有若已有 `.num`／`td[align]` 之類的類別就沿用；沒有就以「表格層級」class `tight-mobile` ＋ `td,th{white-space:nowrap}` 處理，長文字欄個別放行）。
- ≤660px：儲存格左右內距縮到 6px 上下、字級最多縮到 0.875em（不要更小）；欄名太長就在語意斷點放 `<br>`（「股票跌<br>40%」），不要讓瀏覽器亂斷。
- 適用：3、4、8、12、13、14、15、22、25、26、28、29、30、31、33、45，以及其他你量到「≤12 個字的格子被折成兩行」的表。目標：這些表在 375px **不用橫向滑、短字不折行**；做不到的（預期只有下面兩類）才留橫向捲動。
- 2（`s2`，物價倍數，9 欄 × 2 列橫排）：改成直排（兩欄：幾年後／物價倍數，8 列）。這是 HTML 結構改動，內容與數字一個不動；`numbers` 不應有 LOST。
- 23、24（`s11`，兩張查表 8 欄 × 12 列）與 31（`cases`，阿凱 5 欄）若塞不下：維持橫向捲動，但**第一欄 `position:sticky; left:0`**（要有不透明底色與右側細線，深色模式同步），數字不折行。

## 驗收（由 Fable 在瀏覽器量；你先靜態把關）

375px、摺疊全開：
1. 文字 ≤12 個字的儲存格不得被折成兩行以上（欄名裡刻意放的 `<br>` 除外）；
2. 除了 23、24（與塞不下的 31）之外，`.table-wrap` 的 `scrollWidth - clientWidth ≤ 2`；
3. ≥3 欄的表，任何一格不得超過 8 行；
4. 電腦寬度（≥900px）與列印：所有表的外觀與現在相同（CSS 都在 ≤660px 的 media 裡、JS 轉置的卡片在寬螢幕不顯示）；
5. 「← 表格可左右滑動 →」提示仍然只出現在真的能滑的表上（`is-scrollable` 量測要在疊卡完成後再跑一次）。

**不要跑無頭瀏覽器。** 你交件後 Fable 會用上面的條件量一次，把沒過的表號回給你修。
