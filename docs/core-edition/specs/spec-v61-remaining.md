## 分批（避免同時改同一處）

1. **第一批：文字的刪重複與回填**（D1–D5、D7–D9、L1–L5、L7、S8、D6＋D11 的內容搬移）。按「節」分工：同一節的所有題目交給同一個起草代理，產出 guidetools 補丁，主線合併套用。
2. **第二批：結構**（S5 移節、S7 目錄、D10＋S6 列印規則、D6 之後的節名）。一個 builder 依序做。
3. **第三批：三張新圖**（G8、G9、G10）。
4. **第四批：G11 新內容**（研究→起草→驗證）。

每一批：`python3 tools/build_lite.py` 全綠 → 裁判（fable）驗內容沒遺失、數字沒變、連結節號對 → 國中生讀者讀改過的節 → 修 → commit。

## 硬規則（每一批都適用）

- 單一來源：只改 `guide/index.html`（第三、四批另可改 `tools/calc_core.py`、`tools/essay_charts.py`）。
- **不新增事實與數字**（圖表批的新計算除外，數字一律來自 `calc_core.py`）；刪掉的事實一定要在正典位置找得到。
- 不動：黃框 `div.story`（一字不改）、重點句 `mark.key` 文字、`lite/facts.txt` 列的句子（逐字）、工作表還在用的四個區塊（`plan-blank`、`lookup-tables`、`ch4-drill`、`#ten div.warning`；`app-a-checklist` 只在 L5 動）。
- 連結：節 id ≠ 顯示節號——`#s12` 顯示第 13 節、`#s13` 顯示第 14 節、`#cases` 是第 12 節。名詞連結每節只標第一次出現。
- 寫法照 `eli5-rules.md`「寫法」一節；指路句要讓讀者知道去那裡會看到什麼，不要只丟「見第 N 節」。
